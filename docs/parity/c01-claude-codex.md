**Top 10 most user-visible problems**
1. **No restart copy of readings (#12).** Open shows the last quota, accounts and billing at launch from `last-usage-report.json`. Next shows "Reading account usage" until each provider's first reading completes. Claude is fifth in Next's reader queue, so its quota appears late (#6). **Fixed 2026-10-20.**
2. **Codex Desktop approval cards break (CD23, CD24).** When Computer Use or a browser approval offers "always", Next renders the object `{"persist":"always"}` as a React child and the card fails. The allow button says "Allow once" but grants the whole conversation (`persist:"session"`). **Fixed 2026-10-21.**
3. **No age cutoff and no tail-first reading (#19, #20, #5).** Next reads every Claude and Codex log ever written, each from byte 0, at 16 MB per pass with a pass every 5 s. On first launch or after a parser upgrade, "Indexing N transcript files" can stay for minutes and live sessions lag. Totals also include usage older than Open's 31-day ledger. **#5 fixed 2026-10-21** (reads every 2 s while indexing). **#19 fixed 2026-10-21**, as decided that day: only logs last written within the 31-day retention are read, and a first launch reads all of them; tail-first reading (#20) is not built.
4. **Claude tokens dedupe differently (#44, #45).** Next keeps the per-counter maximum per `message.id`, where Open counts the first line of a response. Next drops usage lines with no `message.id` and records no thinking (reasoning) tokens. **Fixed 2026-10-21:** the maximum stays, as better (older Claude Code builds wrote part of the output on a response's first lines); lines without an id count by request id or offset; thinking tokens are reasoning.
5. **Codex guardian (auto-review) usage is missing from totals and statistics (#77).** **Fixed 2026-10-21.**
6. **Session "% of window" uses different sums (#59).** Next uses input + output + cache reads; Open uses input + cache writes + output. **Fixed 2026-10-21.**
7. **Titles, labels and notice text differ (#41, #48, #79, #49, #80, #89, #38, #70, #87, #37, CD21).**
   - Claude has no custom or AI titles and no 60-character first-line rule; untitled sessions show the UUID.
   - No client labels (CLI, Desktop, IDE, exec). **Fixed 2026-10-21**; Codex titles' fallbacks fixed 2026-10-21.
   - No Codex window catalog, month/year names or short labels. **Fixed 2026-10-20.**
   - Every provider and approval notice is English-only and less specific. **Language fixed 2026-10-20**; the wording is Next's own. Claude engine, Codex engine and quota-service failures use Open's words since 2026-10-21.
8. **Running-turn text is missing (#82, #54).** Codex commentary messages and Claude Desktop narration are not shown while a turn runs. **Fixed 2026-10-21.**
9. **Lines over 1 MiB are skipped with a notice (#24).** Next shows "contains an oversized record; usage may be incomplete", and calls whose results were in that line stay open. **Fixed 2026-10-21.**
10. **Navigation and archiving are degraded (#78, #85, #61, CD1).**
    - Archived Codex threads stay listed.
    - Codex Desktop threads only navigate when client hooks are on, which is off by default.
    - Archiving in Claude Desktop is not picked up until a log changes.
    - Daemon iTerm targets are resolved once, at hook time.
    - **Fixed 2026-10-21:** the first three (#78, #85, #61); CD1 is still open.

## 5. Architecture notes

**Serial-read rule violations.** The account worker and the collector share `CollectionGate`, but several UI-triggered paths read logs without taking the gate. These reads can overlap an in-flight account reading (an engine process or HTTP request).
- `N:crates/host/src/lib.rs:364-365` takes the gate only for `snapshot` and `refresh`.
- `set_provider` runs `core.snapshot()` → `scan()`, which reads logs (`N:crates/core/src/lib.rs:514-529`).
- `request_snapshot` from `presentation_request`/`source_update` (`N:crates/host/src/lib.rs:388`) runs `read_reminded()` → `scan_impl` when a reminder is due (`N:crates/runtime/src/lib.rs:234-247`).
- `render_snapshot` → `ensure_usage_projection` reads Claude Desktop metadata (`N:crates/core/src/ingestion.rs:941`) and WorkBuddy metering files on `set_setting`.

**Persistence of conversation text.** Open never persists answer text. Next writes turn messages and desktop-ask text into checkpoint payloads (#58).

**Business logic placement.** Session order and live-first ranking are computed in TS (`SessionsSection.tsx:69-76`), while Open keeps them in Core. It matches today, but it is logic in the UI.

**Structural divergence.**
- Next folds all transcript sources into one generic `Log` reader. Per-provider policy is string matches on `source` inside shared core files, for example `ingestion.rs:119-141` and `log_files.rs:221-313`. Open uses per-provider `TailLog` types.
- `presentation.rs:33` hard-codes Claude Desktop targeting.
- `lib.rs:835-901` hard-codes the Claude window share with raw SQL.

**OS-specific code in shared files.**
- `N:crates/agents/src/claude/transcript.rs:645` hard-codes `Library/Application Support/Claude` inside the portable core. The core claims "no system frameworks", but this is a macOS-only path in shared code.
- `N:crates/platform/src/navigation.rs:39-50` repeats the same macOS path outside `os/`.

**Codex Desktop and origins (sub-audit).**
- Daemon-origin lookup moved out of Open's serial collection pass into hook processes (`origins.rs:740-752`). It does daemon IPC, a full process scan and `lsof` children, outside the gate, possibly several at once.
- The Desktop stream thread and per-answer threads read IPC outside the gate, as in Open.
- `hooks/origins.rs` mixes macOS libproc and sysctl code (277-384, 617-752), Linux `/proc` parsing (385-427) and the unix socket client, all in one shared module with no gate. `clients/codex/desktop_io.rs` mixes macOS `sun_len`/`SO_NOSIGPIPE` with Linux `MSG_NOSIGNAL`.
- On Linux the Desktop observer keeps retrying a connection that cannot exist.
- Native-approval labels, the always-rule and badges are derived in TypeScript (`PermissionToolCard.tsx`); Open does this in core (`PermissionRequest.swift:101-186`). This placement is the root of the CD23 and CD24 bugs.

**Account requests.** Next spawns the Claude and Codex engines with stderr discarded, so failure reasons are lost (#70, #87). There is no per-provider failure backoff beyond the 60 s spacing.
