**Top 10 most user-visible problems:**

1. **Client hooks are dead in the shipped Next build.**
   - Installing requires a host-delegated "fixed hook-owner executable". The stock `main.rs` passes none, and the hook socket only listens after a successful install.
   - As a result, Next has no HUD approvals, questions or plans, no completion, attention, compaction or origin hooks, no Codex Desktop, Antigravity or DeepSeek observers, and no Pi or OpenCode observers.
   - Open turns hooks on by default; Next defaults them off. The docs call both choices deliberate (#49, #50, #66).
2. **Opening the HUD panel, the Statistics window, Settings → Sources or the menu no longer refreshes account quotas** (Open's `refreshAccounts`). Quota shown can be up to about 6 minutes old, or older until a reset (#15).
3. **No restart copy at launch.** Quota and balance rows show "loading" until each account is read again, one at a time (#22). **Fixed 2026-10-20.**
4. **A local log scan can run in parallel with an account reading.** `set_provider` and presentation `request_snapshot` read logs without taking the collection gate. This breaks the hard serial-read rule (#20).
5. **DeepSeek questions:**
   - A failed answer removes the card instead of offering it again.
   - A stream reconnect brings back a question the user had left to Harness.
   - Discovery runs two `ps` processes every 2 s, even when Harness is not installed (#77–79).
6. **Ledger never expires token history** (Open keeps 31 days). The database grows without bound, against the decision to keep 30 days of token history (#36). **Fixed 2026-10-20.**
7. **Cache rewrites (recached tokens) are missing everywhere.** In addition, turn calls have no tools, no context, no per-call list price and no sub-agent calls, and turn breakdowns come from the parser instead of the ledger (#26, #28, #40).
8. **DeepSeek balance run-out time** is estimated from local spend instead of the balance's fall over the last day. Open's balance samples are gone (#38).
9. **Initial indexing runs every 5 s instead of every 2 s**, so "Indexing N transcript files" lasts longer on first launch (#5).
10. **No single-instance lock.** Two Next copies can run at once and both collect into the same database (#83). **Fixed 2026-10-20.**

Other smaller visible changes:
- New DeepSeek rows are shown by default (#30).
- The Statistics bucket choices per range differ (#25).
- Session status labels differ (#24).
- A corrupt database stops collection instead of being recreated (#44).
- Earlier completions of completion-hook clients are lost (#60).

## Architecture notes

- **Serial-read violation (hard rule).** The collection gate is taken only for `snapshot` and `refresh` (`crates/host/src/lib.rs:364-365`).
  - `set_provider` (core `lib.rs:514-530` → `snapshot()` → `scan()`) and presentation `request_snapshot` (`lib.rs:388, 400` → runtime `read_reminded()`) read logs while the account worker may hold the gate for an HTTP or engine reading (`accounts/mod.rs:509-516`).
  - Fix: take `CollectionGate` for every method that can scan: `set_provider`, `request_snapshot`, and any generic-path call in `Runtime::request`.
- **Possible second collector.** `crates/engine` in non-`--app-channel` mode builds its own `Runtime` (watcher, DB, account worker). Nothing stops it from running beside the desktop app; `packages/engine-client` defaults to 'standalone'. Not verified whether any shipped path does this.
- **Observer threads poll in parallel with collection.** Antigravity (2 s HTTP), DeepSeek (2 s `ps` ×2 plus WebSocket) and Codex Desktop each run on their own thread. Open's observers run concurrently with collection too. These are request channels, not provider reads, so this matches Open. However, the DeepSeek process listing is new load (#77).
- **OS-specific code in shared files.**
  - `crates/platform/src/hooks/mod.rs` mixes `#[cfg(unix)]`, `#[cfg(windows)]` and `#[cfg(any(target_os="macos",target_os="linux"))]` branches in `configure()`, including a duplicated Antigravity start in the Windows branch that can never compile in.
  - `completion.rs`, `transcript.rs` and `inbox.rs` each carry inline `cfg(unix)`/`cfg(windows)` ownership checks; these belong in the `os` module.
- **Business logic that Open keeps in Core:**
  - Ledger-level semantics (turn breakdown, cache rewrites, per-call context and tools) are missing rather than moved.
  - Statistics bucket/range rules live in React (`Statistics.tsx:70-75`), where Open keeps them in `StatsRange.bucketSizes` (Core).
  - Session status labels live in `SessionTheme.tsx` rather than the store.
- **Per-pass cost.** Every 5 s, Next reloads `settings.json` (`reload_preferences` on every core request) and renders and diffs a full snapshot. Open re-renders only on change and ticks its clock every 10 s.
