**Top 10 most user-visible problems**
1. **Quota-row forecast and sampling text (#17).** Next builds it in TypeScript, in English only. Exhaustion shows as a clock time ("Tue 16:10") instead of "Exhausts ~2h 10m" / "耗尽 ~2小时10分". Durations are floored and read "2h 0m". The fallbacks read "No forecast" and "Unavailable" instead of "Insufficient data" / "记录不足". The Chinese UI shows these strings in English.
2. **List prices ignore the client's platform (#15, #84, #85, #80).** **Fixed 2026-10-20** for coding plans and DeepSeek; API-key endpoints remain (#84). Next prices every statistic and every quota-window cost on the International list in USD. Open shows ¥ for clients on China platforms (GLM, Kimi, Qwen, MiMo, a DeepSeek CNY account). Next also prices a China-only model (glm-5-turbo) in CNY, where Open leaves it unpriced.
3. **Glow (#6, #5).** Next draws one band per vendor, taken from its tightest window, where Open draws one band per window. API balances never colour the glow, and no balance warning or critical level exists: in Open, ¥10 / $2 is a warning, and zero or an unavailable account is critical.
4. **Logo queue membership (#41, #64).** **Fixed 2026-10-21.** Next shows every detected, enabled provider even with no quota row and no session in the last 24 h. It ignores the live-status switch. It counts a vendor whose only session waits for approval as not working. DeepSeek does not start hidden.
5. **Fresh-install defaults (#89, #90, #91, #93).** **Fixed 2026-10-21.** Language is zh-CN (Open follows macOS). Appearance is dark (Open: system). Launch at login is off (Open: on). Live status is on for clients that were not detected (Open: off).
6. **Statistics model names (#83).** Statistics shows raw model ids such as `claude-opus-4-5-20251101`. Open shows the consumer name: "Opus 4.5", "Kimi For Coding", "model · route".
7. **Sessions lose client and project identity (#62, #60).** **Partly fixed 2026-10-21:** projects group worktrees (#60); Statistics names the client in its Sessions list, search and session page (#62); reply alerts still do not. "Codex Desktop", "Codex CLI", "Claude Code IDE extension" and the other client names are gone. Git worktrees of one repository no longer form one project.
8. **Session detail breakdown (#66–#71).** **Fixed 2026-10-21** (#69 better: tools are recorded in the ledger as logs are read). Before it, missing: turns by prompt (Next lists per response, at most 128), re-cached tokens, peak context, per-turn and per-session list cost, DeepSeek billed session cost, the tools each call asked for, the context window and fill from the catalog, and WorkBuddy credits.
9. **Account header and reset labels (#37, #39, #40).** The plan badge shows raw `max_20x` instead of "Max x20". "Current account" / "Last read 2h ago" and the account notices are missing. A passed reset shows "0m" instead of "Pending update". Resets beyond 24 h show an English weekday without the next-week marker.
10. **Token and money formatting (#100, #103).** **Fixed 2026-10-20** (shared formatters); on 2026-10-21 the Statistics window's remaining money text followed (c10 #90, #60). Statistics and Sessions show "12.5K" / "1.3K" / "5B" (Intl compact) instead of "12k" / "1.3k" / "5.0B". CNY balances show "CN¥8.85" instead of "¥8.85".

## 5. Architecture notes

**Business logic in TypeScript that Open keeps in Core.** This breaks the project's rule that the core computes and the displays only display.
- `packages/ui/src/hud/model.ts:123-185` (`vendorsFromSnapshot`) decides queue membership, each vendor's level, "working" counts and balance text. Open does this in `ReportView.queueVendors` and `glowSegments`.
- `packages/ui/src/hud/bots/mark-director.ts:210-270` (`botQueue`) ports `ReportView.queueMarks`: exhausted-until and the limited logic.
- `packages/ui/src/hud/quota-metrics.ts` composes the forecast, sampling and reset texts. Open composes them in `QuotaForecast` and `QuotaSampling`, which also handle localisation.
- `apps/desktop/src/lib/use-tray.ts:7-23` duplicates the reset countdown from `quota-metrics.ts:51-62`.
- Cache hit rate is computed in TS in `ProviderCard.tsx:369-376` and `SessionDetailView.tsx:556-563`.
- `SessionDetailView.tsx:81-235` reconstructs turns and calls and invents a compaction heuristic.
- `StatsTheme.tsx:181-195` (cost text) and `:307` (shares) format in TS.
- `model.ts:188-196` derives short window names with a regex. **Fixed 2026-10-20.**
- `SourcesSettings.tsx` and `SessionsSection.tsx` apply live-status defaults.
- Several Rust metrics return English prose (`metering.rs:814-898`, `statistics/mod.rs:357-375`, `billing_metrics.rs:163`) that the UI shows verbatim. That bakes language into the core payload, against Open's L10n pairs.

**Formatting duplicated three ways.** Tokens are formatted by `formatTokens` and by three Intl-compact `compact` helpers. Money is formatted by `shortMoney`, `money`, the Workspace `money` and `costText`. One core-side or shared formatter is needed for parity.

**I/O in the render path.** `billing_metrics.rs:72-81` calls `canonicalize()` on the file system for every billing row on every snapshot render. `lib.rs:880ff` (`claude_window_shares`) runs a SQLite aggregate on every render. Neither is a collection read, so the serial rule is not violated, but both are per-render work.

**Pricing region is hard-wired.** (Fixed 2026-10-20: `pricing::PriceRegions` from the readers' services.) `Region::International` is fixed at four call sites (`statistics/mod.rs:170`, `metering.rs:642`, `usage_buckets.rs:106`, plus the default). A PriceRegions equivalent would need service and endpoint facts from the platform accounts layer.

**Catalog loses data.** The Rust `Model` struct (`pricing/mod.rs:152-159`) does not deserialise `contextWindow`, although `catalog.json` carries it for every model.

**Serial collection.** Nothing in the Next code read for this chunk runs provider, account or log reads in parallel. `platform/accounts/mod.rs` reads one account at a time under the collection gate.

**OS-specific code.** None found in the shared core files read here. `legacy_preferences.rs` sits under `os/macos`.
