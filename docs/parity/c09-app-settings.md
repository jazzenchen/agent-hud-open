**Top 10 most user-visible problems**

1. **The HUD is hidden after a fresh start.** Core defaults `hudVisible:false`. App.tsx turns that into `visible:false` for every HUD window. Nothing imports or defaults it to true, so the notch HUD does not appear until the user finds "Show HUD" in the Settings sidebar's "…" menu. Open has no way to hide the HUD at all. **Fixed 2026-10-21:** the HUD is shown by default.
2. **The Settings window and a Dock icon open at every launch, including login launches, and there is no onboarding.** The main window has no `visible:false`, and setup switches to the Regular activation policy. Open starts as an accessory, shows nothing on a normal launch, and on first launch shows the one-screen "Your notch is ready" onboarding window.
3. **Fresh-install defaults differ** (Next core `lib.rs:181` against Open `Settings.swift:114-127`):

   | Setting | Next | Open |
   |---|---|---|
   | language | ~~`zh-CN`~~ System (fixed 2026-10-20) | System |
   | appearance | ~~`dark`~~ System (fixed 2026-10-20) | System |
   | launchAtLogin | `false` (never registered) | `true`, registered on first start |
   | clientHooks | `false` (and the switch is disabled in builds without a delegated fixed executable) | `true` |
4. **No single-instance guard.** A second copy runs beside the first. The user sees two menu-bar items and two HUDs, and the hooks point at whichever copy installed last. Open shows "Agent HUD is already running" and quits. **Fixed 2026-10-20**, and a second launch of the same app now brings it forward (#3).
5. **macOS notifications and a sound are offered.** General → Reminders has "Play a sound" and "System notifications · Allow…". Island events are then posted as UNUserNotifications or as the "Ping" sound. The app also queries UNUserNotificationCenter while it builds the status projection, starting at launch. Decided: the Mac app never uses macOS notifications; alerts appear on the HUD only. **Notifications removed 2026-10-20** (#40); the sound removed 2026-10-21 (#40b).
6. **The menu-bar icon's outline and palette follow the primary HUD's appearance setting, not the menu bar.** With a Dark HUD on a light menu bar the outline is near-white (242) and disappears. With a Light HUD on a dark menu bar it is near-black.
7. **The menu-bar menu differs throughout.** It is a native NSMenu instead of the screen-look panel:
   - windows are not grouped under their account, and account headers lose the plan and the "Current account" / "Last read …" value;
   - no icons, no critical-red figures and no tooltips (forecast, account notice, balance cost);
   - reset labels read "2h 14m", "0m", and English "Sun 02:00" instead of "2h14m", "<1m", "Pending update" and localized "Next …";
   - extra "Statistics…" and "Refresh data" items, and no host items.
8. **The Agents page is a different design:**
   - account visibility is per display instead of global;
   - the Copilot quota switch turns on with no consent dialog;
   - the "Agent" and "Client readings" sections (Pi and OpenCode observer state) are missing;
   - it adds a provider "Enabled" switch, an API-credentials form and developer notices that are always in English. (The developer notices are gone since 2026-10-20.)
9. **The Display page breaks the shared-layout model.**
   - Toggling any Expanded-panel switch forks the display into its own layout.
   - There is no "Shared layout" row and no "Use Shared Layout" button.
   - The HUD-style "Revert to Previous" lives only in component memory, so it is lost when the user switches display, leaves the page or restarts.
10. **"Language: System" is ignored in places, and developer UI ships in Settings.**
    - The menu-bar menu and the Agents page test `language.startsWith("zh")`, so on a Chinese Mac set to System they show English.
    - Settings shows developer UI: a built-in "Updates" placeholder ("Unavailable"), a "Migration status" page, an Experimental → "Development" section, and the footer "Agent HUD 0.1.0 · Live". (Migration page and Development section removed 2026-10-20; the Updates placeholder now says the preview does not update itself, in both languages.)

## Architecture notes (Next)

**Business logic in TS that Open keeps in Swift or Core:**
- The menu-bar projection lives in the host (`tray.rs`, 2026-10-21): grouping, the "No quota reading" row, the figure, levels, and a reset-countdown formatter that still duplicates Countdown/AgentRow with different output. It no longer depends on a Settings webview.
- The island-event → native alert policy is in App.tsx:511.
- HUD window sizing plans are in the host (`hud/plans.rs`, 2026-10-21); a Simple strip's label widths are estimated there on the wide side.
- The reset-style undo is component state (DisplayPane.tsx:92-138).
- Language "System" is resolved three ways:
  - useText (SettingsPrimitives.tsx:42-48) is correct;
  - App.tsx:346-350 is correct;
  - SourcesSettings.tsx:14 is wrong (the tray now reads the snapshot's resolved language).

**Defaults are duplicated and inconsistent:**
- `core/src/lib.rs:181`;
- `lib/demo.ts:40`;
- `packages/protocol/hud-defaults.json`;
- `DisplayPane.tsx:65-74` (`layoutDefault`);
- the approval choices in GeneralPane.tsx:200, core lib.rs (three places) and legacy_preferences.rs:525.

None of these carries Open's defaults for language, appearance, launchAtLogin and clientHooks, and `hudVisible` has no Open counterpart.

**OS-specific code in shared files:**
- `host/src/lib.rs` inlines the macOS Carbon hot-key module (452-567) and the activation-policy logic in the shared host. They are cfg-gated but should sit in a platform module, as `system/` already does.
- `mcp_clients.rs:29-66` mixes macOS `Codex.app` paths, Windows `APPDATA`/`.exe`/`.cmd` and Unix PATH in one function.

**Serial-collection rule:**
- `crates/runtime/src/lib.rs:121-123` says the host holds the collection gate for "snapshot", "refresh" and "request_snapshot". Account workers hold the gate across their I/O (`platform/src/accounts/mod.rs:513`).
- But `native_request` takes the gate only for `snapshot|refresh` (src-tauri lib.rs:364-365). `presentation_request` "source_update" and "save" call `request_snapshot` with no gate (lib.rs:388,400).
- `request_snapshot` can call `core.read_reminded()` (runtime lib.rs:234-242), which reads logs.
- So a log read can run concurrently with an account read, against the strict-serial rule.

**Blocking native calls on the collector:**
- `System::project` runs inside `install_snapshot` on the collector thread with the Backend lock held (lib.rs:36-38).
- On a cache miss (the first pass, and after login-item changes) it calls `target::status()`, which waits up to 5 s on `UNUserNotificationCenter getNotificationSettings` (system/macos.rs:66-91).
- That stalls a collection pass and contacts Notification Center on every launch. Decided: the Mac app never uses macOS notifications; alerts appear on the HUD only. **Resolved 2026-10-20:** the status no longer asks Notification Center anything.

**Missing seams:**
- The ProductExtension interface (extension.rs) has no menu-item contribution, Settings sections on Experimental, or HUD controls hook. Open offers all three (`additionalMenuItems`, `experimentalSettings`, `additionalHUDControls`). Since 2026-10-21 the Settings frontend takes a product host's additions to Agents → Agent plugins (`App`'s `agentPlugins`): switches in the Claude Code plugin's row or rows of their own in a client's card.
- Extension pages are appended after the built-in pages; there is no Experimental page since 2026-10-21.
