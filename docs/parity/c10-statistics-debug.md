**Top 10 most user-visible problems**
1. **No session costs anywhere.** (List-price costs since 2026-10-21, #87.) Core writes `"cost": null` for every session (`database/checkpoints.rs:155`), so rows, folded day headers, the Today card ("费用 —") and the session page's Cost all show nothing. (#87, #70, #67)
2. **The session page shows a different data model.** Bars are per usage entry (each assistant message or `token_count` event), not per prompt turn, and they stack cache reads and writes together as "Cache". There is no Token/Cost switch, no sub-agent or re-cache marks, and no turn calls with tools. The context-window chart and "Last reply" never render, because parsers always write `context: null` and `message: null`. Turns, Quota share, Credits and Metered context are gone from the figures. (#79-#86)
3. **Session rows are thinner.** They have no per-turn sparkline, no turn count, and no context bar except for WorkBuddy. They show raw model and source ids, a full path instead of `~/…`, and "空闲 · 5 分钟前更新" instead of "state · N 轮 · 12m". There is no Reveal-log menu. (#71-#75)
4. **Every token figure in the window uses a different number format.** **Fixed 2026-10-20** (#89). Next shows `48K / 1M / 12.3M` where Open shows `48k / 1.0M / 12M` (`Intl` compact instead of `TokenFormat.short`, which `packages/ui` already ports). (#89)
5. **Model names are raw and colours are hashed.** (Names fixed 2026-10-21, #26; colours still hashed, #25.) Names are the raw model string (`claude-opus-4-5-20251101` instead of "Opus 4.5"). Colours come from a hash of the model id instead of the report order, so they no longer match the HUD or Open. (#25, #26)
6. **Agent cards differ.** They only exist for agents with usage in the range and are ordered by tokens, not by Settings order. The Cost cell follows the kind selection instead of the all-kinds price. "Cache reads ≈ N% of cost" comes from hard-coded weights, re-cache cost is missing, and the balance moved to a separate "API balances" section. (#48-#58)
7. **The chart controls and labels differ.** (Edge buckets fixed 2026-10-21, #29, with the hover card's partial note, #32.) Bucket choices per range differ, and switching range picks a different bucket. Axis labels lack the weekday and "Now". Edge buckets are clipped. The hover card lacks the period end and the partial or empty notes. (#6, #7, #23, #29, #32)
8. **The model filter narrows the whole page.** In Next it also narrows agent cards, Recent usage and the heatmap, and a new Agents filter does the same. Deselecting the last model returns to All. In Open the filter is local to the chart. (#20-#22)
9. **None of the recording and debug flags exist** (`--record*`, `--demo-script`, `--demo-clock`, `--snapshot`). Under `--demo` the Tokens page shows an error ("This demo has no usage ledger…"), so demo videos and stills of the statistics cannot be produced. (#93-#98)
10. **Pricing is always international, and money text differs.** (Pricing fixed 2026-10-20, #91; money text fixed 2026-10-21, #90.) CNY-billed DeepSeek and China clients are priced in USD. Amounts lose "≈" and show `CN¥`, with currencies in alphabetical order rather than USD first. (#90, #91)

Also notable:
- The project filter has no Git-repo or worktree grouping, and the source filter lists raw ids (#13, #14).
- "在访达中显示日志" first navigates to the session's client and only reveals the log as a fallback (#77).
- The window no longer fits its height to the content (#18).

## Architecture notes (Next)

1. **Business logic in TS that Open keeps in Core:**
   - Day filing, the Today card and folded-day sums (`SessionStatistics.tsx:135-153`, `SessionListSection.tsx:31-48`; Open `UsageStore.sessionsByDay`).
   - Cache hit rate (`ProviderCard.tsx:369-376`, `SessionDetailView.tsx:496-562`; Open `TokenKinds.cacheHitRate`).
   - The cache-cost share from invented weights (`ProviderCard.tsx:81-90`; Open `AgentUsage.cacheReadShare` from catalog prices).
   - A compaction heuristic (`SessionDetailView.tsx:81-118`). Removed in the Sessions redesign of 2026-10-21; Core marks compactions.
   - Guessing the shape of untyped `calls` JSON (`SessionDetailView.tsx:120-266`). Removed in the Sessions redesign of 2026-10-21; Core gives a turn its calls.
   - Model colour hashing (`StatsTheme.tsx:160-164`).
   - The range→bucket validity table (`Statistics.tsx:70-75`), which is duplicated by Rust's own 30-day override (`statistics/query.rs:72`).
   - Day boundaries use the JS local `Date` in Sessions (`SessionTheme.tsx:144-148`) but chrono-tz in Rust statistics.
2. **The protocol promises row fields that Core never fills.** `Session.cost`, `turnCount`, `usage` and `contextPercent` (`packages/protocol/src/index.ts:76-81`) are always null or absent in list rows (`database/checkpoints.rs:155`). The UI renders placeholders instead of failing, which hides the gap (#70-#74, #87). Likewise, turn `context` and `message` are always null (`agents/src/claude/transcript.rs:116-121`), which leaves dead UI branches (#82, #86).
3. **Duplicated formatting and themes.**
   - The desktop app has two token formatters (`StatsTheme.compact`, `SessionTheme.compact`) and its own money formatters, while `packages/ui` has the `TokenFormat.short` port (`formatTokens`).
   - `StatsTheme.themeFor` and `SessionTheme.themeFor` duplicate palettes, and both diverge from Open's `Theme.kind`.
   - One shared formatting module, mirroring Core's `TokenFormat` and `MoneyFormat`, would fix #89 and #90 everywhere.
4. **OS-specific code in shared UI is minor.** `SessionDetailView.tsx:803` branches on `connection.platform === "macos"` for the Finder label. `capture.rs` is split per OS properly.
5. **No parallel collection reads were found.** `statistics`, `sessions` and `session_detail` go through `Runtime::local_query(&mut self)` (`crates/runtime/src/lib.rs:185-191`), so they serialize with collection. `session_detail` does parse a log on demand (`sessions.rs:519`): a UI-triggered source read, serialized but outside the collector's pass. `open_session` also re-runs `session_detail` before navigating (`runtime/lib.rs:214-216`).
6. **Debug and recording tooling has no home in Next.** There is no counterpart for the debug-only still renderer, the recorder or the scripted demo, and the earlier audit did not list them as gaps. If they are wanted, they belong in the Tauri shell behind a dev feature flag, rendering the existing DOM surfaces.
